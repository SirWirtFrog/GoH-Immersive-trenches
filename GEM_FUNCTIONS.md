# Справочник нативных функций GEM

Карта функций, изученных для ImmersiveTrenchesMod. В неё входят функции, которые мод вызывает или перехватывает, и внутренние функции GEM, разобранные при диагностике строительства и сетевых заглушек. Имена в таблицах рабочие, если оригинальное имя неизвестно.

## Поддерживаемые исполняемые файлы

| Процесс | ProductVersion | PE TimeDateStamp | SizeOfImage |
| --- | --- | --- | --- |
| `call_to_arms.exe` | `1.0.6.7-aaa36ed4d` | `0x6ab3dcc7` | `0x1707000` |
| `call_to_arms_ed.exe` | `1.0.6.7-aaa36ed4d` | `0x6ab3dd83` | `0x1533000` |

Все адреса ниже — **RVA**, то есть смещения от базы соответствующего EXE в памяти. Для вызова или точки останова используйте `moduleBase + RVA`. В таблицах `—` означает, что адрес для редактора в проекте не установлен. Указатели `void*` обозначают пока непрозрачные объекты GEM. Сигнатуры взяты из вызовов в моде. Типы, восстановленные только по машинному коду, и неизвестные части ABI помечены отдельно.

ABI — Windows x64. Первые четыре целочисленных аргумента передаются в RCX, RDX, R8 и R9, включая `this` для методов. При входе в функцию пятый и шестой аргументы находятся по `RSP+0x28` и `RSP+0x30`. Перед переносом на новую сборку проверьте PE-заголовок, указатели в таблицах и цель каждой перехватываемой инструкции `call`/`jmp`. Для проверки ASLR используйте фактическую базу загруженного EXE.

### Внутренности регистрации, восстановленные по дизассемблированию

Эти адреса используются для анализа, прямых вызовов из мода нет. Сигнатуры здесь предполагаемые, кроме явно наблюдаемой записи поля ID.

| Функция или участок | RVA игры | Наблюдаемый ABI и поведение |
| --- | --- | --- |
| Внутренняя регистрация в спавне | `0x7063ef` | Инструкция `call 0xa60150` внутри реализации запроса. На входе RCX — сущность, DL — `1`, R8B — выбор пула. |
| Выдать или учесть ID сущности | `0xa5fee0` | Предполагаемая сигнатура `uint32_t*(uint32_t* outId, void* entity, bool clientIdPool)`. Вызывается из `0xa60150` по `0xa60287`. Третий аргумент выбирает ветку 5 только при исходном ID `0xffffffff`. Уже назначенный ID обрабатывается через существующий пул. |
| Ветка локального пула | `0xa5ffa0` | Внутренняя метка, самостоятельной сигнатуры нет. Использует базу пула из `manager+0xf0` и аллокатор слотов из `manager+0xf8`. База `0x18000` записывается при инициализации по `0xa6102c`. |
| Получить менеджер ID | `0xa60f30` | Наблюдаемый ABI `void*()`. Возвращает адрес менеджера, используемый регистратором и функцией выдачи ID. |
| Найти пул по существующему ID | `0xa60c30` | Предполагаемая сигнатура `void*(void* manager, const uint32_t* id)`. Из возвращённой записи читаются база пула `+0x08` и указатель на хранилище слотов `+0x10`. |
| Записать ID сущности | `0x6fc830` | Наблюдаемые аргументы `(void* entity, const uint32_t* id)`. Записывает `*id` в `entity+0xc0`, затем передаёт управление следующей функции. Возврат отдельно не восстановлен. |

В сетевом логе старой сборки заглушки получали ID вида `0x0000a001` и `0x0000e002`, из тех же пулов, что и объекты сервера. В текущем коде локальный флаг запроса и аргумент выбора локального ID применяются вместе. Вызов регистрации меняется только для одной клиентской заглушки на текущем потоке. После этой правки размещение заглушек нужно подтвердить в сетевой игре.

## Известные структуры и поля

| Объект | Известная раскладка |
| --- | --- |
| `TrenchVector` | Три последовательных `float`: X, Y, Z. Размер `0x0c`. |
| `TrenchTarget` | Размер `0xa8`. `flags` (`uint32_t`) в `+0x00`, `first` в `+0x04`, `second` в `+0x10`. Мод меняет цель при `flags == 1`. Исходный угол вычисляется по `second - first`. |
| `TrenchTransform` | Размер `0x30`. Оси X/Y/Z в `+0x00` / `+0x0c` / `+0x18`, мировая позиция в `+0x24`. |
| Сущность GEM | Флаги в `+0x38`, трансформация в `+0x50`, позиция в `+0x74`, скелет в `+0xb0`, ID в `+0xc0`, строка имени типа в `+0xf0`. Мод считает сущность живой, если ID и указатель совпадают в дереве и `(flags & 0x10020) == 0`. Перед финальной посадкой заглушки сбрасываются биты выравнивания по грунту `0x1c`. |
| Кость | Флаг грязного кэша `+0x10`, бит `1`. Мировая ось X в `+0xa8`, мировая позиция в `+0xcc`. У прямой секции используются пары `point1/point5` и `point4/point8`. |
| `SpawnRequest` | Размер `0x140`, выравнивание 16. Флаги в `+0x00`, строка типа в `+0x08`, начальный ID `0xffffffff` в `+0x30`, три стартовых `float` в `+0x70`, два объекта имени размером `0x60` в `+0x80` и `+0xe0`. |
| Строка MSVC x64 | 16 байт встроенного буфера или указатель в `+0x00`, длина в `+0x10`, ёмкость в `+0x18`. При ёмкости меньше 16 используется встроенный буфер. |
| `eFortify::Action` и данные превью | Имя модели в `action+0x890`, поворот в радианах в `action+0x8bc`. Бит `0x20` первого байта `options` добавляет четверть оборота. Границы `GemPreviewBounds.min/max` в `+0x08` / `+0x14`. Вектор результатов в `output+0x70`, запись `0x10` байт, флаг допустимости в `+0x0c`. |
| Инструкции и приказ | Имя типа для `install` в `instruction+0x10`, имя типа для `ia:spawn` в `action+0x50`. Ссылка на действие в приказе распределителя в `order+0x390`. |
| Сетевая команда размещения | Байтовый признак в `+0x08`, флаги `uint16_t` в `+0x18`, подтип в `+0x42`, действие в `+0x48`, цель в `+0x50`, байт режима в `+0xf8` при флаге `0x80`. Фильтр мода проверяет признак `1`, подтип вне `{1, 2}` и `(flags & 0x18) == 0x18`. |
| Сетевое превью | Ключ `FortifyPreviewKey`: ID `uint64_t` в `+0x00`, признак `local` в `+0x08`. У `visual` строка модели в `+0x00`, диапазон записей в `+0x70`, yaw в радианах в `+0x88`. Запись позиции размером `0x10` состоит из XYZ и `uint32_t state`. Дерево превью в игре по RVA `0x15a2700`, у узлов ключ в `+0x20`, признак `local` в `+0x28`. |
| Узел дерева сущностей | Указатели `left/parent/right` в `+0x00` / `+0x08` / `+0x10`, `nil` в `+0x19`, ID в `+0x20`, указатель сущности в `+0x28`. |
| `PanelPage` и регистрация кнопки | Страница имеет размер `0x38`, указатели вектора записей начинаются в `+0x20`. Имя кнопки в записи лежит в `entry+0x48`. `ButtonRegistration` содержит `const char* name` и `ButtonFactory factory`. |

## Как сверять при дальнейшей отладке

- Одиночный режим. Сравнить `preview_snap`, `order_reserved`, `install_target` и `completed`. Записи `[GEM caps] completed` и `height_updated` показывают позицию заглушки после выравнивания сцены.
- Сетевой режим. Проверить `writers=2/2`, затем `net_send_snap`, `preview_received`, `preview_removed` и `scene_add` в пределах одного PID. У заглушек сравнить `position` якоря с `actual_position` сущности. Событие `lost` означает, что ранее запомненная сущность больше не проходит проверку по ID и указателю.
- Лог находится в `%TEMP%\GoH\ImmersiveTrenchesMod.log`. `RIB_Main` относится к Miles Sound System, а `GoHModInitialize` — к DLL мода. Они перечислены в [README](README.md).
- Внешняя карта COA Script Extender хранится в локальной копии [examples/coa_script_extender](examples/coa_script_extender). Основные файлы — [каталог функций](examples/coa_script_extender/analysis/ai/coa_ai_master_functions.txt), [точки перехвата](examples/coa_script_extender/analysis/ai/coa_ai_master_hooks.txt) и [определения SDK](examples/coa_script_extender/sdk/coa_sdk.h). Это отдельный каталог кандидатов с собственной нумерацией и степенью проверки. Перед использованием каждого адреса нужно сверить исполняемый файл, ссылки на функцию, ABI и раскладку объекта.
