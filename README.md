# ImmersiveTrenchesMod

Нативный мод для Call to Arms – Gates of Hell: Ostfront загружается через Miles Sound System.

- `ImmersiveTrenchesMod.asi` экспортирует `RIB_Main` для Miles. При `upDown == 1` загрузчик определяет корень игры по пути к ASI, открывает `mods\ImmersiveTrenches\ImmersiveTrenchesModLogic.dll` по полному пути и вызывает её экспорт `GoHModInitialize`.
- `ImmersiveTrenchesModLogic.dll` содержит логику мода и остаётся загруженной до выхода из процесса. Инициализация выполняется один раз за процесс, даже если Miles перезагружает ASI. Сейчас она записывает PID редактора в `%TEMP%\GoH\ImmersiveTrenchesMod.log` и в окно Output отладчика.

`RIB_Main` возвращает `1`. Ошибки загрузки DLL видны в окне Output отладчика. `DllMain` обоих модулей сразу возвращает `TRUE`.

## Установка из релиза

1. Закройте игру и GEM Editor.
2. Скачайте ZIP для Windows x64 из раздела [Releases](https://github.com/SirWirtFrog/GoH-Immersive-trenches/releases) и распакуйте его. Скопируйте папки `binaries` и `mods` из архива в корень игры, где уже находятся одноимённые папки.
3. Запустите игру и активируйте **Immersive Trenches** в списке модов. Выберите инженера и нажмите **Модовые окопы** на основной панели, под кнопкой **Развернуть**.

Релиз собран для версии игры **1.067.0 x64** (сборка `aaa36ed4d`). Файл `ImmersiveTrenchesMod.ini` больше не используется; оставшийся от прежней версии файл можно удалить.

## Build → Deploy → F5

Для сборки и установки текущей версии выполните из PowerShell:

```powershell
.\Install.ps1
# Тот же процесс установки напрямую:
.\deploy.ps1
# Другой каталог игры или конфигурация:
.\deploy.ps1 -GameRoot 'D:\Games\Gates of Hell' -Configuration Debug
```

`Install.ps1` запускает общий `deploy.ps1` и принимает те же параметры
`-GameRoot`, `-Configuration` и `-MSBuildPath`. Нужен полный checkout проекта;
это установка из исходников со сборкой, требующая Visual Studio/Build Tools.
Установка также убирает отключённые ресурсы строительства пулемётов,
сохраняя их резервные копии в `out/deploy-backups/disabled-mg`.

Скрипт по умолчанию собирает Release x64, находит MSBuild через PATH или
Visual Studio Installer и выполняет Deploy и DeployResources. Игру, редактор
и локальный сервер нужно закрыть. Устаревший INI удаляется, установленные
файлы проверяются по SHA-256. Старые папки огневых позиций после переименования
сохраняются в `out/deploy-backups` и удаляются из игры, чтобы не было дублей.
Если PowerShell блокирует запуск скриптов, используйте
`powershell -ExecutionPolicy Bypass -File .\deploy.ps1`.

`DeployResources` также убирает устаревшие каталоги после переноса ресурсов
в `resource/entity/landscape/cut_entity/IT/dirt/trench_dirt_*` и исправления
имени `mg-nest` на `mg_nest`. Убираются только отсутствующие
в исходниках каталоги с известным новым соответствием или дублирующими DEF.
Перед копированием они перемещаются за пределы ресурсов игры в
`%LOCALAPPDATA%\ImmersiveTrenches\resource-backups\<дата-id>` с manifest.json.
Это предотвращает одновременную загрузку старого и нового определения одной
сущности, например `it_trench_dirt_straight` с разными контурами cut.
Посторонние пользовательские каталоги и установленные DLL сохраняются.
При запущенной игре/редакторе этой установки операция останавливается.
Проверка плана без изменения файлов:

```powershell
.\scripts\DeployResources.ps1 -SourceRoot .\mods\ImmersiveTrenches -DestinationRoot 'E:\SteamLibrary\steamapps\common\Call to Arms - Gates of Hell\mods\ImmersiveTrenches' -PlanOnly
```

Нужны Visual Studio 2026 с компонентом **Desktop development with C++** для F5, набор инструментов MSVC v145 и Windows SDK. Сборку и развёртывание также можно выполнить через Build Tools 2026.

1. Откройте `ImmersiveTrenchesMod.sln`, выберите `Debug|x64` и соберите решение. Оба модуля и их PDB появятся в `out\x64\Debug\`. Выходной каталог для `Release|x64` — `out\x64\Release\`.
2. Остановите предыдущую отладочную сессию и закройте открытый GEM Editor, предварительно сохранив свою работу. Из корня проекта выполните в Developer PowerShell for VS 2026:

   ```powershell
   MSBuild.exe .\ImmersiveTrenchesMod.vcxproj /t:Deploy /p:Configuration=Debug /p:Platform=x64
   ```

   `Deploy` проверяет установку игры и копирует уже собранный `ImmersiveTrenchesMod.asi` в `binaries\x64\mss`, а `ImmersiveTrenchesModLogic.dll` — в `mods\ImmersiveTrenches`. PDB остаются в каталоге сборки.
3. Выберите `ImmersiveTrenchesMod` запускаемым проектом, поставьте точку останова на вызов `LogInitialization()` в `src\ImmersiveTrenchesModLogic.cpp` и нажмите F5. Профиль Local Windows Debugger запускает `call_to_arms_ed.exe` с рабочим каталогом `binaries\x64`. После продолжения выполнения проверьте свежую строку в логе.

   ```powershell
   Get-Content "$env:TEMP\GoH\ImmersiveTrenchesMod.log" -Tail 5
   ```

Корень игры по умолчанию — `E:\SteamLibrary\steamapps\common\Call to Arms - Gates of Hell`. Для другой установки задайте переменную окружения `GoHGameRoot` до запуска Visual Studio и Developer PowerShell. Один параметр задаёт каталог и для Deploy, и для F5.

## Удаление мода

Закройте игру, GEM Editor и локальный сервер, затем выполните скрипт рядом с `deploy.ps1`:

```powershell
.\uninstall.ps1 -WhatIf # Посмотреть, что будет удалено
.\uninstall.ps1         # Удалить установленный мод
# Для другой установки игры:
.\uninstall.ps1 -GameRoot 'D:\Games\Gates of Hell'
```

Корень игры определяется так же, как при установке: параметр `-GameRoot`,
переменная `GoHGameRoot`, затем стандартный путь на диске E. Скрипт удаляет
`binaries\x64\mss\ImmersiveTrenchesMod.asi`, его PDB при наличии и всю папку
`mods\ImmersiveTrenches`, включая DLL, настройки и оставшиеся старые ресурсы.
Файлы игры, другие моды, исходники и внешние резервные копии сохраняются.
Повторный запуск допустим. При запущенной игре или обнаружении ссылок/junction
в путях удаления скрипт останавливается. Для удаления Visual Studio не требуется.

## Диагностика строительства GEM

После Deploy и перезапуска игры или редактора в `%TEMP%\GoH\ImmersiveTrenchesMod.log` появится строка `[GEM construction] Trace enabled`. При вызове `install`, `install_begin` или `install_end` туда же записываются имя инструкции, PID, TID и значения регистров с аргументами. Оригинальная инструкция выполняется с теми же аргументами.

Диагностика проверяет PE-заголовок и адреса оригинальных функций для игры и редактора сборки `1.0.6.7-aaa36ed4d`. При несовпадении пишет `Trace skipped`. Для остановки в Visual Studio поставьте точку останова в `LogGemConstruction`.

Для модовой прямой секции ожидается дополнительная строка `section_created` с указателем на созданную сущность. Следующая строка `exit_anchors` содержит исходные позиции точек стыка без смещения и направление локальной оси X левого выхода. Правый выход развёрнут на 180° относительно левого.

DLL отслеживает точки стыка модовых секций и ставит заглушки `it_trench_dirt_end_cap` на свободных торцах. После выравнивания костей прямой секции обновляется высота заглушек. При занятии стыка заглушка убирается.

Чтобы видеть тот же лог в PowerShell во время игры:

```powershell
Get-Content -LiteralPath "$env:TEMP\GoH\ImmersiveTrenchesMod.log" -Tail 30 -Wait
```

Прямая секция использует инструкцию `install`. Для проверки `install_begin` и `install_end` можно построить штатную пулемётную позицию, например `heavy_mg_mg34`.

## Ресурсный мод

Из корня проекта выполните команду в Developer PowerShell for VS 2026 при закрытой игре.

```powershell
MSBuild.exe .\ImmersiveTrenchesMod.vcxproj /t:DeployResources /p:Platform=x64
```

На странице **Модовые окопы** доступны прямые секции, изгибы, огневые позиции и другие модули. При наведении рядом со свободной точкой стыка новая секция прилипает к ней и разворачивается.

### Пулемётное гнездо

Строится только секция окопа. Ящик и достройка пулемёта временно отключены.
Наработки сохранены отдельно в `archived_features` со снимком и SHA-256.

## Модель состояния и автономные проверки

Папки огневых позиций в `resource/entity/landscape/cut_entity/IT/dirt`:
`trench_dirt_fire_position_through` — проходная позиция с двумя стыками,
`trench_dirt_fire_position_dead_end` — тупиковая с одним стыком.
Внутренние ID `it_trench_dirt_fire_position_through` и `it_trench_dirt_fire_position_dead_end` сохранены.

Пересечение вырезов модовых окопов блокирует превью и выдачу приказа.
На сетевом клиенте допуск команды дополнительно проверяется перед отправкой:
это распространяется и на свободное размещение без прилипания к стыку.
Допустимое перекрытие у соединяемых стыков сохраняется. Причина отказа
пишется в лог как `net_send_blocked` (`section_overlap` или `queued_overlap`).

Состояние секций, якорей, соединений, резерваций и заглушек принадлежит
`trench::State` (`src/TrenchState.cpp`). Геометрия и переходы состояния работают
без GEM через интерфейс `trench::Engine`. `src/GemTrenchSnap.cpp` реализует этот
интерфейс: читает память игры, устанавливает перехваты и вызывает нативные функции.
Общие типы геометрии находятся в `src/TrenchTypes.h`.

Автономные проверки модели не запускают игру. Из Developer PowerShell:

```powershell
MSBuild.exe .\tests\TrenchStateTests.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64
.\out\tests\Debug\TrenchStateTests.exe
```

Проверки охватывают принятие и отклонение приказа, отмену, уничтожение приказа
до возврата из очереди, переход к готовой секции, пересечения и сетевые заглушки.
Они не заменяют проверку ABI, превью и строительства в игре и редакторе.

Проверка файлового каталога и сохранения геометрии при переносе из старой версии:

```powershell
MSBuild.exe .\tests\TrenchCatalogTests.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64
.\out\tests\Debug\TrenchCatalogTests.exe
```

Она сравнивает 22 варианта со старым каталогом, проверяет разбор файлов, отсутствующие ресурсы, конфликты имён, разреженные ID, четыре стыка и разбиение вогнутого контура. Старый каталог сохранён только в `tests/fixtures/LegacyTrenchCatalog.inc` как эталон теста; DLL его не использует.

## Файлы якорей секций

DLL при запуске находит `.trench` в `resource/entity` относительно своей папки и собирает каталог. Рядом с каждой моделью секции находится файл с тем же базовым именем и расширением `.trench`. Для секции пулемётного гнезда используется одна модель `it_trench_dirt_mg_nest.mdl` и один файл `it_trench_dirt_mg_nest.trench`. У выхода файл называется `it_trench_dirt_exit.trench`, как его модель.

Пример для короткой прямой:

```text
{it_trench
    {version 1}
    {variant "it_trench_dirt_straight_short"
        {preview "it_trench_dirt_straight_short_preview"}
    }
    {default_socket 0}
    {socket 0
        {position -56.517 -0.201 0}
        {yaw 180}
    }
    {socket 1
        {position 53.631 -0.201 0}
        {yaw 0}
    }
}
```

Каждый `variant` связывает готовую сущность с превью по игровым именам без `.def`. Их определения должны находиться рядом с `.trench`; готовая сущность должна ссылаться на соответствующую модель, а превью — на существующую модель внутри этого мода. Несколько вариантов в одном файле разделяют геометрию. Имена сущностей и превью используют префикс `it_trench_`, ASCII-буквы, цифры и подчёркивания, длина — до 63 символов.

Формат поддерживает от одного до четырёх стыков. `position` задаётся относительно начала модели, `yaw` — направление наружу в градусах от +X к +Y. Сейчас Z должен быть равен нулю: прилипание остаётся плоским. ID — постоянные неотрицательные числа, могут иметь пропуски; порядок записи блоков не влияет на результат. `default_socket` указывает ID, а не индекс в файле. Комментарии начинаются с `;`. `overlap` и `OutwardOffset` в `.trench` не задаются.

Контур читается из верхнеуровневого `area "cut"` соседней `.mdl`. Поддерживается один `polygon2` с `radius 0`, вершинами XY и флагом `rotate`, от 3 до 64 вершин; вогнутые простые контуры автоматически разбиваются на треугольники. Самопересечения, ненулевой радиус и неподдерживаемые конструкции контура отклоняются. В превью и служебные объекты без стыков отдельные `.trench` не добавляются. Файлы не подключаются через `include` или `extension` в ресурсах GEM.

Файл без `variant` считается заготовкой и не регистрирует постройку. Экспериментальный четырёхсторонний перекрёсток зарегистрирован для проверки четырёх стыков, поэтому всего в каталоге 23 варианта из 17 файлов. Его меш и `cut` пока трёхсторонние, а четвёртый стык предварительный: строительство и прилипание можно проверять, но физического четвёртого прохода в модели ещё нет.

Ошибки записываются в обычный лог с PID, путём, строкой и причиной. Неисправный файл не мешает загрузке остальных. При конфликте имени сущности или превью конфликтующие варианты не регистрируются. Превью, выдача приказа и сетевая отправка блокируют модовые действия с неизвестным превью `it_trench_*`; штатные игровые постройки продолжают работать. Встроенного запасного каталога нет.

Загрузка выполняется один раз до подключения обработчиков; после изменения файлов нужен перезапуск. Поддерживаются распакованные ресурсы своего мода. Для добавления обычной секции пересборка DLL не требуется: добавьте модель, `.def` и `.trench`, действие, навык инженера, кнопку и подписи, затем выполните DeployResources. При обновлении на эту версию установите DLL и ресурсы вместе; у всех участников сетевой игры должны совпадать определения секций.

## Смещение стыков

Смещение при прилипании зафиксировано в DLL: `snapOutwardOffset = -8.0f` в `src/TrenchState.cpp`. Оно действует вдоль оси стыка для всех модовых секций и сдвигает новую секцию к существующей на 8 игровых единиц.

Общий допуск пересечения вырезов у соединения также зафиксирован в DLL: `seamOverlap = 10.0f`. Для изменения этих значений нужна пересборка DLL. Настроек через INI сейчас нет; Deploy и DeployResources удаляют устаревший `ImmersiveTrenchesMod.ini` из установленного мода.

## Сборка и проверка экспорта из консоли


```powershell
MSBuild.exe .\ImmersiveTrenchesMod.sln /t:Build /p:Configuration=Debug /p:Platform=x64
dumpbin.exe /headers /exports .\out\x64\Debug\ImmersiveTrenchesMod.asi
dumpbin.exe /headers /exports .\out\x64\Debug\ImmersiveTrenchesModLogic.dll
```

В выводе для обоих модулей должна быть архитектура `8664 machine (x64)`, для ASI — экспорт `RIB_Main`, для DLL — `GoHModInitialize`. Проверенный ProductVersion редактора — `1.0.6.7-aaa36ed4d`. Перед будущими перехватами GEM сверяйте фактическую сборку редактора.

Свободные торцы закрываются заглушками. Старый автоспавн выходов, его кости-якоря
и диагностический перехват удалены. Отдельная секция «Выход» остаётся доступной в меню.
